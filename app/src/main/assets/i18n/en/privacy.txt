Data Stored on Your Device
Bookmarks, favorites and reading progress, browsing history, address bar search terms, open tabs, default search engine and custom search URL templates, site rules, custom CSS/JS/HTML, appearance and site certificate exceptions are saved locally. Sites may store cookies, cache, and site storage data via WebView. Address bar suggestions are matched locally against search terms and browsing history; text you type is not sent to suggestion services. Only after you submit a search is the query sent to the chosen search service. Bookmarks and favorites cache site icons obtained during browsing; if no icon is found, the site’s /favicon.ico may be requested directly, without using third-party icon proxies or sending full bookmark paths or URL parameters. This data is not automatically sent to the developer’s servers by installing this app. The app has no built-in account system, usage statistics, or error reporting services.

Google Bookmarks, Favorites, and SkyEye Settings Sync (Optional)
Only after you link your Google account does the app use the drive.appdata permission to read/write this app’s dedicated hidden Google Drive data space; it does not access other Drive files. Synced data includes bookmark names, URLs, folders, modification and deletion records, and sync device identifiers generated by the app. Favorites sync identifiers, custom names, current reading URLs, page titles, scroll positions, reading percentages, modification times, and deletion status. Google account IDs and emails identify the sync account. Enabling “Sync SkyEye Site Settings” also syncs domains, component rules, custom CSS/JS/HTML, site behavior settings, and modification/deletion status; code may contain private content—please verify before syncing. Browsing history, address bar search terms, search engine choices and custom templates, temporary exceptions, certificate exceptions, and OpenRouter keys are excluded from sync. Sync may occur automatically when the app opens or selected data changes. For the same favorite, the newest complete record is used; it does not enforce highest reading percentage or force navigation to the currently viewed page. Older app versions do not sync favorites; update all devices to supported versions for sync.

Google Data Use is limited to requested sync functions, complying with Google API Services User Data Policy including Limited Use requirements; Google account or cloud sync data is not shared with AI providers for model training. Google services handle data per their privacy policy: https://policies.google.com/privacy

AI Assistance (Optional)
You may choose not to use AI or select local Gemma 4 E2B or OpenRouter.

Gemma 4 Local Model
Only after you initiate download will approximately 2.59 GB of the model be obtained via Android Download Service from Hugging Face’s LiteRT community model repository; the source receives your IP and download request, handled per https://huggingface.co/privacy. After integrity verification, the model is stored locally; analysis runs on-device without sending queries, page structure, or custom code to AI cloud services. No API key is required; you may delete the downloaded model in AI settings. Requires compatible 64-bit device with sufficient storage and memory.

OpenRouter Cloud Model
After entering your OpenRouter API key, it is protected by Android Keystore and stored locally. Only with your consent and after pressing analyze will the current domain, limited component structure, saved custom CSS/JS/HTML and component rules, and your input question be sent to OpenRouter and the selected model provider for SkyEye rule checking. Regular SkyEye analysis uses limited structure only; in “AI Rule Revision,” with your consent, the current document load, pre-SkyEye limited raw HTML snapshot, and current edits are also sent. HTML excludes form controls, editable areas, scripts, event attributes, and query parameters in URL attributes but may contain private page text; this snapshot remains in page memory only and is not written to disk. The app does not read form values or cookies; however, questions, component names, rules, and custom code may contain personal data you or sites entered; edited HTML may also include original component text—please verify content. The API key authenticates with OpenRouter and is not provided to webpages. The app specifies data_collection=deny to exclude model providers that allow data collection. OpenRouter account logs, billing, and other data processing follow their policies and account settings. Policy: https://openrouter.ai/privacy

Browsing Sites and Version Queries
When opening webpages, the site and its loaded resources receive network requests, IP address, browser identification, and applicable cookies. When you submit search text from the address bar, it is URL-encoded and sent to your chosen Google, Bing, Yahoo, Baidu, Naver, Chinese Wikipedia, or custom HTTPS search service; search results, available regions, and data handling are governed by that service’s policies. Queries for the latest Chromium version connect to Google’s version service; manual AI model list updates connect to OpenRouter. HTTP/HTTPS files are handled by Android Download Service; blobs/data files generated by webpages are written locally in segments to Downloads/ChengJing and are not uploaded to the app’s servers. Such downloads require the source tab to remain available; cancellations or interruptions clean up incomplete output. Downloaded files and records remain on the device and are not cleared by incognito tab clearing; new temporary file downloads do not save incognito source URLs. Long-pressing images verifies and saves them; bookmark import/export uses only files you select via the system.

Connections and Custom Code
Google sync and OpenRouter native connections use HTTPS certificate verification. Web browsing verifies certificates by default; you may manually allow permanent exceptions for specific HTTPS hostnames (including different ports but excluding other subdomains) via the address bar connection icon. Exceptions persist until you close the app, reducing site identity assurance and showing warnings in the address bar. HTTP sites are unencrypted. JavaScript you add has the capabilities of page scripts and may read content or send requests; use only code you understand.

Saving, Stopping, and Deleting
Local data is managed by each feature. Browsing history retains up to 250 recent pages; search terms up to 100 entries; site icon cache retains up to 30 days, 256 entries, and 8 MiB; webpage cache is managed by WebView capacity. You may clear history records, delete bookmarks or favorites, remove domain rules, delete API keys in AI settings, or disable site certificate exceptions via the connection icon. To prevent offline devices from restoring deleted favorites, deletion records with original fields and deletion status are kept in sync logs; these no longer appear in favorites lists. To remove all local data (including site cookies, storage, and sync deletion records), use Android Settings → Apps → ChengJing Browser → Storage → Clear Data, or uninstall; this resets the app—export needed bookmarks first.

“Stop Sync and Logout” halts app sync but retains local and Google Drive bookmarks, favorites, reading progress, and site settings. To delete cloud data, first stop sync on all devices, then delete hidden app data in Google Drive web version under Settings → Manage Apps → ChengJing Browser; you may also revoke access on your Google account’s third-party connections page. Re-linking devices with existing data may re-upload selected local sync data. Data sent to OpenRouter or model providers must be handled or deletion requested per those services. The developer cannot directly read or delete your device, Google Drive, or personal OpenRouter account data.

Default Search Engines (1.9.0)
Settings → Browsing lets you choose Google, Bing, Yahoo, Baidu, Naver, Chinese Wikipedia, or provide your own HTTPS search URL template containing a single {query}. Google is the default. Choices and custom templates are saved locally and excluded from Google sync; clearing app data or uninstalling removes them. The address bar first locally distinguishes explicit URLs from search text; typed content is not sent to online suggestion services. Only submitted searches send queries to the chosen service. Incognito uses the same settings but does not add search terms to local browsing history. Custom services are your choice; verify their URLs and privacy policies.

Incognito Tabs and Download List (1.4.0)
Incognito tabs use a separate WebView profile from regular tabs, not sharing cookies, cache, or site storage. They do not add to local browsing or search history, do not save tab URLs for restoration, nor generate tab preview thumbnails. Closing all incognito tabs triggers asynchronous clearing of that profile’s cookies, network cache, and site storage. If the process crashes, the next launch clears old incognito profiles and does not reuse that session. This does not guarantee complete invisibility to OS or forensic tools, nor hide your activity from sites, employers, or network providers.
Bookmarks, favorites, site rules, and system downloads you create are retained. Before incognito downloads, you are reminded of file and system download record retention; active sharing, AI analysis, and other outbound actions follow original confirmations and service policies. Android System WebView supporting data isolation and clearing is required; if unsupported, update prompts appear, and incognito is not faked by regular tabs.
The download list queries only system download records created by this app and does not scan other apps’ files; records removed by the system may not be recoverable. Regular tab previews may include visible page content; since 1.4.1, these are stored in the app’s internal private space, retained with tabs, deleted when tabs close; reopening the app does not delete them. Snapshots are excluded from Google sync, albums, Downloads, and system backups. Incognito tabs do not generate or save snapshots. Clearing all app data or uninstalling deletes these local snapshots.

Home Page and Daily Quotes
Home button toggle, custom home URL, whether the initial guide was seen, and daily quote start date are saved locally and excluded from Google sync. 89 quotes are provided offline with the app, without querying or uploading reading records to any service. Actively clicking the custom home sends a normal browsing request to that site; incognito tabs use separate site data. Clearing app data resets these local settings.

Delete Browsing Data (1.6.0)
The feature menu lets you select a time range to delete local browsing/search history or close the last regular tab visited in that period and delete its snapshot. Time info is stored only locally and excluded from Google sync. Older data without timestamps is deleted only under “All time.” Cookies, cache, and site data are separately selectable for full clearing, unchecked by default and not limited by the selected time range; this may log you out of sites. This operation preserves bookmarks, favorites, downloads, SkyEye settings, and incognito sessions; incognito data is cleared by closing incognito tabs.

Open Other Apps (1.7.0)
Clicking external app links in webpages or URLs designated by Android to be handled by apps causes ChengJing to hand off the link to the corresponding app. The other app may save links and usage records per its policies; ChengJing does not provide browsing cookies, history, or API keys. Incognito mode warns before leaving because the other app is not controlled by ChengJing’s incognito clearing. ChengJing only queries handlers for HTTP/HTTPS links and does not save or upload installed app lists. If the corresponding app is not installed and the link has a valid web fallback, it opens in the current tab.

Image Operations (1.8.0)
Long-pressing images allows preview, copy, download, share, or open in a new tab. Image requests use that tab’s cookies and browser identification; images are cached locally, max 32 MiB per image, 128 MiB general cache, 64 MiB incognito cache, clearing files older than 24 hours on startup and writes. Clearing cookies, cache, and site data also clears general image cache. The system may reclaim cache earlier; files downloaded to Downloads are kept or deleted by you. New image download records max 500 entries, excluded from Google sync. Copying and sharing provide the actual file via temporary read permissions limited to that image; receiving apps may keep copies per their policies. Incognito previews clear when all incognito tabs close; incognito copy, download, or share warn about possible external retention. data:/blob: temporary image tabs do not save for restoration; prompts suggest downloading first.

Site Location (1.11.0)
Only if a site requests location and you allow both the site and Android location permission will WebView provide the device location to that site. You can choose approximate or precise location; the app does not request background location, does not save coordinates, nor send location to the developer, Google sync, or AI services. Site use of location is governed by their policies. Regular site location permissions are saved locally and can be changed via the address bar site info; excluded from Google sync. Incognito permissions are separate and cleared when all incognito tabs close or the app exits. You may revoke app location permission in Android settings; clearing app data or uninstalling removes local permissions.

Android Direct Location (1.11.1)
With site and Android permission granted, ChengJing directly requests location from Android’s GPS, network, or fused sources and provides it to the current site. Sites may request single or continuous location; requests stop on cancel, page change, tab close, or leaving foreground. Single requests wait up to two minutes, possibly shorter per site settings. Location modules only briefly use coordinates in memory without recording or syncing. Site-displayed location info remains webpage content; regular tab previews retain visible content per existing rules; incognito tabs do not generate previews. The system may save recent locations, used only within site-accepted timeframes. Site location permissions, incognito isolation, and exclusion from Google/AI sync remain consistent.
