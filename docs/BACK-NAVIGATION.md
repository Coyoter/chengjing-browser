# 返回行為（1.9.1）

舊邏輯在網頁無法返回時，先建立一個首頁分頁，再關閉網頁。外部連結每次新增分頁，返回又把它換成空白頁，因而持續累積。

新規則：

1. 網站提示、圖片預覽、全螢幕、選單與天眼選取仍先關閉自己的介面。
2. 有較早網頁時正常返回；內建首頁（空網址／about:blank）不是可返回的網頁歷史。明確的 HTTP／HTTPS 自訂首頁仍保留。
3. 到達瀏覽起點後直接讓 Android 顯示前一個 App 或桌面。外部連結的臨時分頁會移除；一般自行開啟的頁面保留，不另建首頁。
4. 最後一個臨時分頁關閉時保存空清單；只有使用者再次打開瀏覽器時，才建立一個可操作的新分頁。
5. 外部連結可以使用目前尚未瀏覽的空分頁；含有真實歷史、圖片或無痕的分頁不會被當成空位覆蓋。

`openedExternally` 與分頁穩定識別碼一起保存，舊資料預設 false。MainActivity 處理外部網址後會清除 Intent 中已消費的 data，避免重建再次新增。退出使用 `moveTaskToBack(true)`，讓系統決定回到來源工作或桌面，不自行啟動 referrer 指定的應用；參考 [Android 工作與返回堆疊](https://developer.android.com/guide/components/activities/tasks-and-back-stack)。

驗證包括歷史篩選單元測試、實際 WebView 的跨首頁返回、連續外部連結、不重複重建、舊資料相容，以及獨立外部 App 在正式最佳化版中真正開啟瀏覽器再透過系統 Back 返回。此更新不批次刪除先前已有的空白分頁。
