# 外觀與互動一致性檢查（1.8.1）

## 根本問題

主畫面原先以 Compose 自行選擇深色配色，Activity 的 Android 主題卻固定為 Theme.Material.Light。兩套設定彼此沒有同步。因此 App 選深色、系統維持淺色時，原生長按選單、無痕／下載／匯入提示等會顯示白色方框；WebView 的色彩偏好也可能仍是淺色。

這次以 AppCompat DayNight 管理 Activity 資源，外觀偏好是可觀察的單一狀態。Compose 與原生元件共用 values／values-night 色票，移除另一份獨立配色。App 自有的命令選單與確認提示集中於 BrowserPrompts，頁面切換、關閉或取消時，不執行已失效的操作；網站提示會回覆原本的 JsResult／JsPromptResult。

## 設計基準

延續暖白、墨綠與玉綠操作色，不另換品牌。文字使用系統無襯線：一般動作 16sp／24sp、說明 14sp／21sp、提示標題 20sp／28sp。長按選單圓角 28dp、列高至少 56dp、圖示 22dp，文字與圖示相距 16dp。長標題截斷並保留來源網域，項目過長可捲動。沿用 Material 的觸控回饋，不新增裝飾動畫。

補全表面層次、反相提示、錯誤與次要文字色，避免元件落回 Material 預設的其他色系。主要文字／操作的使用色對檢查至少 4.5:1 對比。媒體畫面採固定深色，停用按鈕明確淡化。App 自有全螢幕面板的系統列背景與圖示統一處理，保留媒體全螢幕的對比保護。

## 檢查與修正範圍

| 範圍 | 處理 |

| 圖片匯出、無痕下載、外部 App、一般下載、匯入書籤 | 共用確認視窗；確認、取消、失效與返回行為一致 |
| 網站 alert／confirm／prompt／離開提示 | 共用外觀；標示網站來源，保留回傳值及取消語意 |

| 一般與無痕分頁 | 外觀切換不重建 Activity、不關閉分頁、不改網址或捲動位置；向未附掛的背景 WebView 也傳遞設定變化 |
| 主選單、首頁、分頁、瀏覽記錄、下載、書籤、收藏 | 沿用既有結構，共用完整色票；查看深淺色實際畫面 |

## 驗證方法與邊界

AppearanceTest 檢查系統深／淺與 App 深／淺／系統六種組合，讀取實際選單像素，不只檢查狀態值。另檢查文字對比、網站提示實際回傳值、原生下拉選單、無痕確認，以及外觀切換前後的 Activity、WebView、分頁數、導覽代次與捲動位置。主要畫面的截圖存於測試附件的 appearance 目錄。

R8 獨立測試程式在未保留測試類別的最佳化 APK 上，用真正觸控操作設定、圖片選單與外部網址；核對畫面顏色及分頁保留。既有圖片、外部 App、資料清理、收藏及分頁重啟回歸仍保留。公開 Google 圖片頁另外使用選用測試驗證；CI 不依賴外部搜尋服務。

檢查的是 App 自有介面與相關互動，不宣稱涵蓋每個網站、Android 廠商樣式或使用者實體手機。網站可使用自己的配色，沒有深色樣式的網頁維持原樣；Android 分享面板、檔案選擇器、鍵盤及系統權限提示由系統或對應 App 決定，不改動手機全域外觀設定。
